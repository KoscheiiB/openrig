# JSON CLI compatibility: initial contract (v1)

The default compact `rig ps --nodes --json` (without `--full` or `--fields`) continues to print an array of rows, or an existing scope/limit envelope with `entries`. Each **compact node row** now carries `schemaVersion: 1`; the shape is pinned by `packages/cli/test/ps-json-contract.test.ts`.

Required structural field names for this projection, version 1: `schemaVersion`, `rigId`, `rigName`, `logicalId`, `canonicalSessionName`, `hostSelfId`, `runtime`, `model`, `modelObservation`, `sessionStatus`, `startupStatus`, `oriented`, `lifecycleState`, `agentActivity`, `hasAssignedWork`, `assignedWorkCount`, `pendingWorkCount`, `resumeType`, `resumeTokenPresent`, `lastActivity`. These required compact-node fields now survive **wire** JSON serialization even when the observation is missing: unknown values use explicit `null` for identity, session/startup/lifecycle, and work flags/counts. Do not infer operational readiness from a `null` value. The source-structure regression and `packages/cli/test/ps-wire-json-contract.test.ts` both pin the required fields. Optional diagnostics can still be omitted when unavailable. Conditionally-present fields include `communityHarness`, `launchWrapper`, `needsAttention`, `intentionallyStopped`, `storedSessionStatus`, `identityVerdict`, `heldReason`, `startedWithoutRequired`, and `latestError`.

**Compatibility:** adding an optional field preserves v1; removal/rename or a meaning/type change to a required field requires changing the test expectation, documenting the field change and announcing it in the changelog. Increment `schemaVersion` for a breaking compact-node change. This test guards source projection keys, not HTTP daemon behavior. CLI `--full`, custom `--fields`, `rig queue list/show`, and `rig usage` remain unversioned in this initial slice; their evolving output must not be inferred to have this contract. Daemon errors may return an object instead of an expected array; consumers must check exit status and JSON structure.
